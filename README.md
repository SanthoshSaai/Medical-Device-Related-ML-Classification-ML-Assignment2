# MedGuard CTG — Cardiotocography-Based Fetal State Classification

An academic machine-learning project that compares five classical classifiers on cardiotocography (CTG) measurements. The project uses CTG feature measurements from the UCI Machine Learning Repository and predicts the `NSP` fetal-state class: Normal, Suspect, or Pathological.

> **Important use limitation:** This is a classroom machine-learning demonstration. It is not a medical device, clinical decision-support system, or diagnostic tool. Predictions must not be used to make patient-care decisions.

## 1. Problem statement

Cardiotocography records fetal heart-rate and uterine-contraction information. The purpose of this project is to compare five supervised classification algorithms in predicting the fetal-state category (`NSP`) from 21 cardiotocography measurements. The project demonstrates data preparation, model training, evaluation, model persistence, and an interactive results application.

## 2. Dataset description

- **Dataset:** Cardiotocography (CTG)
- **Source:** UCI Machine Learning Repository, dataset ID 193
- **Official URL:** https://archive.ics.uci.edu/dataset/193/cardiotocography
- **UCI-reported instances:** 2,126
- **UCI-reported input features:** 21
- **Task:** Multiclass classification
- **Selected target:** `NSP`
- **Target classes:** 1 = Normal, 2 = Suspect, 3 = Pathological
- **License:** CC BY 4.0
- **Citation:** Campos, D. & Bernardes, J. (2000). Cardiotocography. UCI Machine Learning Repository. https://doi.org/10.24432/C51S4N

The 21 input features are `LB`, `AC`, `FM`, `UC`, `DL`, `DS`, `DP`, `ASTV`, `MSTV`, `ALTV`, `MLTV`, `Width`, `Min`, `Max`, `Nmax`, `Nzeros`, `Mode`, `Mean`, `Median`, `Variance`, and `Tendency`.

The UCI table also contains `CLASS`, a separate expert-assigned target describing morphologic pattern. It is deliberately **not** used as an input feature because it is another target label and could leak outcome information into the `NSP` prediction task.

## 3. Models used

All five required classifiers are trained on the same stratified 80/20 train/test split:

1. Logistic Regression
2. Decision Tree Classifier
3. K-Nearest Neighbors (KNN)
4. Gaussian Naive Bayes
5. Support Vector Machine (SVM, RBF kernel)

Imputation and scaling are kept inside scikit-learn pipelines so preprocessing is fitted only on the training partition. Scaling is used for Logistic Regression, KNN, and SVM. Decision Tree and Gaussian Naive Bayes use median imputation without standardization.

## 4. Evaluation metrics

Each model is evaluated on the held-out test partition using:

- Accuracy
- AUC (macro one-vs-rest)
- Precision (macro)
- Recall (macro)
- F1 score (macro)
- Matthews Correlation Coefficient (MCC)

The multiclass AUC is calculated one-vs-rest and macro-averaged over classes represented in the test data. The training split is stratified so that the three target classes are represented in both partitions.

After executing `train.py`, the actual values are written to `results/model_comparison.csv`. No performance values are prefilled; observations and the overall best model must be based on this generated result, not assumed in advance.

## 6. Run the project

Use Python 3.10 or 3.11 (recommended).

```bash
python -m pip install -r requirements.txt
python train.py
```

The training script fetches the official UCI dataset, checks that there are at least 500 usable rows and at least 12 input features, creates a stratified train/test split, trains all five classifiers, saves their preprocessing/model pipelines, exports the held-out `test_data.csv`, and writes the model comparison and dataset metadata files.

Start the web app after training:

```bash
python -m streamlit run app.py
```

## 7. Streamlit application

The app provides:

- CSV upload for labelled test data (the CSV must include the 21 feature columns and `NSP` target)
- Classifier selection
- A comparison table for all five saved models on the uploaded test CSV
- Accuracy, AUC, Precision, Recall, F1, and MCC
- Confusion matrix and classification report for the selected classifier
- Prediction preview and downloadable predictions CSV

The app loads the saved fitted pipelines. It does **not** retrain on uploaded test data. The uploaded test CSV is evaluated only; it must contain ground-truth `NSP` labels because the assignment requires evaluation metrics.

## 8. Streamlit Community Cloud deployment

1. Run `train.py` successfully first.
2. Confirm the generated five `.joblib` files exist in `model/` and `test_data.csv` exists in the repository root.
3. Push the complete project to the GitHub `main` branch.
4. In Streamlit Community Cloud, create a new app from this repository, select branch `main`, and set `app.py` as the entry point.
5. Open the deployed URL and test the default test data and CSV upload before including the link in the submission PDF.
