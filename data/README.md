# MedGuard CTG: Cardiotocography-Based Fetal State Classification

An academic machine-learning project that compares five classification algorithms on the UCI Cardiotocography (CTG) dataset. The models use 21 CTG measurements to classify the `NSP` target as Normal, Suspect, or Pathological.

> **Academic-use notice:** This project is a machine-learning assignment and demonstration only. It is not a medical device or a clinically validated diagnostic/decision-support system. Its predictions must not be used to make patient-care decisions.

## 1. Problem Statement

Cardiotocography records fetal heart-rate and uterine-contraction information. The objective of this project is to build and compare five supervised machine-learning classifiers that predict the fetal-state category (`NSP`) from 21 cardiotocography measurements. The project demonstrates dataset preparation, model training, model evaluation, saving trained models, and evaluating labelled test data through an interactive Streamlit application.

## 2. Dataset Description

- **Dataset:** Cardiotocography (CTG)
- **Source:** UCI Machine Learning Repository, dataset ID 193
- **Dataset URL:** https://archive.ics.uci.edu/dataset/193/cardiotocography
- **Number of instances:** 2,126
- **Number of input features:** 21
- **Target column:** `NSP`
- **Task:** Three-class classification
- **Target labels:** 1 = Normal, 2 = Suspect, 3 = Pathological
- **Target distribution:** Normal = 1,655; Suspect = 295; Pathological = 176
- **License:** CC BY 4.0

The 21 input features are `LB`, `AC`, `FM`, `UC`, `DL`, `DS`, `DP`, `ASTV`, `MSTV`, `ALTV`, `MLTV`, `Width`, `Min`, `Max`, `Nmax`, `Nzeros`, `Mode`, `Mean`, `Median`, `Variance`, and `Tendency`.

The UCI data also contains a separate target column named `CLASS`. It is excluded from the input features because this project predicts `NSP`; including another target label as an input could cause target leakage.

**Dataset citation:** Campos, D. & Bernardes, J. (2000). *Cardiotocography*. UCI Machine Learning Repository. https://doi.org/10.24432/C51S4N

## 4. Machine Learning Models Used

All five required classification algorithms are trained and evaluated on the same stratified 80:20 training/test split (random state = 42):

1. **Logistic Regression** — a linear classification model that estimates class probabilities.
2. **Decision Tree Classifier** — a tree-based model that learns decision rules from the input features.
3. **K-Nearest Neighbors (KNN)** — classifies a record based on nearby training examples.
4. **Gaussian Naive Bayes** — a probabilistic classifier based on Bayes' theorem and a conditional-independence assumption.
5. **Support Vector Machine (SVM)** — a classifier that learns decision boundaries; this project uses an RBF kernel.

Median imputation is included in the model pipelines. Standard scaling is applied within the pipelines for Logistic Regression, KNN, and SVM. Preprocessing is fitted using only the training partition and is reused for test evaluation.

## 5. Evaluation Metrics and Model Comparison

The models are evaluated on the held-out test partition using the following six metrics:

- **Accuracy:** proportion of all predictions that are correct.
- **AUC:** macro one-vs-rest area under the ROC curve.
- **Precision:** macro-averaged precision across the three classes.
- **Recall:** macro-averaged recall across the three classes.
- **F1 Score:** macro-averaged F1 score across the three classes.
- **MCC:** Matthews Correlation Coefficient, which summarizes agreement between predicted and actual classes.

### Observations on Model Performance

| ML Model Name | Observation about model performance |
|---|---|
| Logistic Regression | Achieved 0.8568 accuracy and 0.9602 AUC. Its recall of 0.8497 indicates that it identifies a substantial proportion of the actual classes, although its F1 and MCC are below those of Decision Tree and SVM in this experiment. |
| Decision Tree | Achieved 0.8850 accuracy and the highest F1 score (0.8263). It provides a strong balance of precision and recall, although its AUC (0.9021) is lower than the other models' AUC values. |
| K-Nearest Neighbors | Achieved the highest accuracy (0.8991) and precision (0.8452). Its recall (0.7470) is lower, showing a trade-off between precision and recall on this test split. |
| Gaussian Naive Bayes | Recorded the lowest accuracy (0.7981), AUC (0.8694), F1 (0.6706), and MCC (0.5710) among the five models in this experiment. It is the weakest performer on this particular split. |
| Support Vector Machine | Achieved the highest AUC (0.9718), recall (0.8710), and MCC (0.7346). Its accuracy is 0.8850 and F1 is 0.8208, making it a strong overall performer in this experiment. |

**Overall model selected: Support Vector Machine (SVM).** SVM is selected based on its highest AUC and MCC, together with the highest recall. Decision Tree has a slightly higher F1 score, while KNN has the highest accuracy; therefore, the preferred model can depend on which evaluation metric is most important for the intended task.

These observations describe this particular train/test split and are not evidence of clinical suitability.

## 7. How to Install and Run the Project

Python 3.11 is recommended for the pinned dependencies.

### Windows PowerShell

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python train.py
streamlit run app.py
```

After Streamlit starts, open the local URL shown in the terminal (normally `http://localhost:8501`).

The training script downloads the UCI dataset, checks the dataset size and feature count, creates the stratified split, trains the five classifiers, and generates the saved models, `test_data.csv`, and evaluation results.

## 8. Streamlit Application and CSV Upload

The Streamlit application provides:

- A CSV upload option for labelled test data.
- A dropdown to select one of the five trained classifiers.
- A comparison table showing the six evaluation metrics for all five models.
- Detailed metrics for the selected model.
- A confusion matrix and classification report.
- A preview of actual and predicted classes.
- A downloadable CSV containing the prediction results.

The uploaded CSV must contain all 21 input feature columns and the `NSP` target column (1, 2, or 3). The target column is required because the app calculates evaluation metrics by comparing predictions with actual labels. When no file is uploaded, the app uses the generated `test_data.csv` by default.

The app loads the five saved model pipelines and evaluates the uploaded test records. **It does not retrain the models on uploaded test data.**

## 9. Streamlit Community Cloud Deployment

1. Push the complete project, including the five saved model files and `test_data.csv`, to the GitHub repository.
2. Sign in to Streamlit Community Cloud using the GitHub account that has access to the repository.
3. Create a new app and select this repository and the `main` branch.
4. Set `app.py` as the application entry point and deploy.
5. Open the public app URL and test that the app loads, displays the model comparison, and accepts the labelled test CSV.
6. Add the final public Streamlit URL to Section 3 of this README and to the assignment PDF.
